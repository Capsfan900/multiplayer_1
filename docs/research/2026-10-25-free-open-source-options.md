# Free and open-source options for multiplayer_1

Research date: **2026-10-25, America/New_York**. Source review completed 2026-10-26 00:25:25 UTC. **Research only; implementation remains paused.** This report proposes no accepted decision change and does not resume the [paused project](../handoffs/2026-10-25-paused-project.md). Linked official documentation, repositories and license files are the source record; prices are USD unless stated otherwise.

## Recommendation

**Keep Photon Fusion Host Mode as the leading option.** For this eight-player Unity FPS, the smallest complete route is likely Fusion's integrated prediction, hitbox rewind and managed connectivity, plus a separately verified minimal identity/profile service. Free software alone is not the same as a complete, free online game service.

**PurrNet + PurrDiction is the most useful open-source challenger to investigate later.** Both repositories are MIT licensed and document prediction and rewind. Its current migration add-on, however, is paid early access, so it does not yet establish a complete free replacement. Mirror is genuinely MIT but leaves more FPS foundation risk; FishNet is free for games under a custom license with paid built-in hitscan rewind. These are engineering judgments from the evidence below, not measured comparisons.

The governing requirements remain in the [foundation](../superpowers/specs/2026-10-25-multiplayer-foundation-design.md): four teams of up to two, private internet friend matches, player hosting, authenticated profiles, reconnect and bounded migration. Preserve the [moving zone and combat](../superpowers/specs/2026-10-25-arena-combat-items-zone-design.md), accepted art, and source reuse. No candidate automatically supplies those game rules.

## Internet connectivity, identity and profiles

To satisfy convenient internet joining across restrictive home networks, some reachable provider must handle discovery/signaling and relay fallback. Persistent recoverable accounts likewise need a trusted identity/storage service. An OSS netcode library removes license fees; it does not operate these services.

| Service path | Free/OSS distinction and practical fit |
| --- | --- |
| **Photon Cloud + proposed PlayFab profiles** | Photon attempts direct UDP after coordination/NAT traversal, then relay fallback. Current development allowance is **20 CCU / 60 GB monthly**; launch allowance **100 CCU / 0.3 TB monthly**, one game app per customer, no CCU burst. These are application/service quotas, not eight free slots per room; regional peaks and both traffic directions matter. [Connection process](https://doc.photonengine.com/fusion/v2/manual/connection-and-matchmaking/connection-process), [pricing](https://www.photonengine.com/fusion/pricing). |

Relay defaults to fallback after direct failure; forcing relay hides peer IPs but adds a network hop. A promising no-rented-server partner for an OSS library, requiring a compatible adapter and product configuration. [Services](https://onlineservices.epicgames.com/), [relay behavior](https://dev.epicgames.com/docs/en-US/api-ref/enums/eos-e-relay-control). |
| **Steamworks** | Useful if Steam is deliberately chosen: Steam identity, invitations/lobbies and Steam Datagram Relay. **PlayFab deserves an eligibility check before it becomes the assumed free profile backend.** Its managed Photon authentication endpoint and token API are documented, making it a practical integration lead. However, current Microsoft pages describe a transition from Development Mode to Foundation Mode, whose eligibility includes shipping or planning Xbox and linking Partner Center. The older Development page contains inconsistent 100/1,000-user wording; the public pricing page was inaccessible during research. Do not promise unrestricted free production profiles for this Windows-only friend game. [Photon integration](https://learn.microsoft.com/en-us/xbox/playfab/live-service-management/service-gateway/add-ons/photon/quickstart), [token API](https://learn.microsoft.com/en-us/rest/api/playfab/client/authentication/get-photon-authentication-token?view=playfab-rest), [transition](https://learn.microsoft.com/en-us/gaming/playfab/pricing/development-mode), [eligibility](https://learn.microsoft.com/en-us/xbox/playfab/get-started/mode-overview).

EOS Connect can use supported external identities or Epic accounts and produces a product-specific user ID; Epic social features have their own account requirements. Recoverability, account linking and private-room authorization must be designed around the chosen login, not an arbitrary device string. EOS storage permissions/limits and the exact Unity adapter remain unverified. [Connect guide](https://dev.epicgames.com/docs/epic-online-services/eos-fundamentals/connect-interface/connect-guide/log-in-with-an-epic-games-account).

For **every** stack, a room code locates a session; it is not proof of identity. Reconnect must securely reclaim the original seat without duplicate control. Lobby owner changes do not restore ammo, timers, projectiles, pickups, zone progress or deduplication history. These are application obligations under the foundation contract.

## Limits that change the decision

A participating host remains trusted and has a latency advantage. Prediction masks local control delay; rewind can award hits after someone reaches cover. Neither prevents a malicious host rewriting the match. Prefer responsive friend matches as the goal; no “lag-free” or ranked-integrity claim follows from any library. [Fusion topology](https://doc.photonengine.com/fusion/v2/fusion-choose), [rewind tradeoff](https://doc.photonengine.com/fusion/v2/manual/advanced/lag-compensation).

Fusion migration restores uploaded state, so upload age and omitted state can lose progress; it is not continuous fault tolerance. Its migration/reconnect samples need adaptation and failure tests. The SDK support list names Unity 6.0/6.3, while the source project is **6000.5.10f1**: exact compatibility is unverified. Do not silently downgrade Unity or replace the approved motor. [SDK support](https://doc.photonengine.com/fusion/v2/getting-started/sdk-download), [migration API](https://doc.photonengine.com/fusion/v2/manual/advanced/host-migration).

## Free production tools worth keeping

**Keep Blender, the audited source helpers and Unity's existing authoring/rendering tools.** Blender is GPL software; Unity Personal is a proprietary free tier, currently for eligible users below **$200,000 revenue/funding over the prior 12 months**. Replacing Unity would discard the reuse benefit and change an accepted decision. [Blender license](https://github.com/blender/blender/blob/main/COPYING), [Unity eligibility](https://unity.com/products/unity-personal).

For the accepted soft modern look, use editable bevelled modular forms, shared matte materials and the existing stock-URP-Lit-versus-stripped-source comparison. Unity already provides Profiler, Frame Debugger, Memory Profiler and Profile Analyzer. No new rendering framework is justified by this research. [URP Lit](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/lit-shader.html), [profiling tools](https://docs.unity3d.com/6000.0/Documentation/Manual/performance-profiling-tools.html).

Follow the [asset pipeline](../ASSET-PIPELINE.md) and [rendering contract](../superpowers/specs/2026-10-25-unity-rendering-design.md): reuse Level Studio, mesh/export validation and selected rig/socket helpers only after their dependency/license audit. Retain source files and GUIDs. Rigify is an optional GPL rig-control tool if the existing helpers prove inadequate, not a reason to add another pipeline. [Rigify manual](https://docs.blender.org/manual/en/4.1/addons/rigging/rigify/index.html).

For a specific lighting-reference gap, Poly Haven's downloadable assets are CC0; select only assets that fit the restrained style, retain provenance and distinguish assets from copyrighted site preview renders. Avoid a generic asset-pack shopping list or GPU generation pipeline. [Asset license](https://polyhaven.com/license).

## Focused follow-up: which comparisons are productive?

**A comparison of complete setups is useful; another broad library survey has diminishing value.** The shortlist below is a research recommendation, not a change to the accepted Fusion decision.

| Setup | Reason to compare | Decision-changing gap |
| --- | --- | --- |
| Fusion Host Mode + Photon Cloud | Baseline with prediction, rewind and managed connectivity in one provider path | Exact Unity compatibility, measured correction/hit behavior, recovery completeness and actual relay usage |
| PurrNet + PurrDiction + EOS | MIT core/prediction and an official EOS adapter offer a credible alternative with less Photon dependence | Whether the migration add-on restores the authoritative prediction state and reconnects players correctly after abrupt host loss |
| FishNet + EOS, optionally Pro | Provider choice and an inexpensive supported rewind option merit a conditional comparison | Custom host migration and the maintenance cost of combining sessions, identity and recovery |

Two findings refine the initial survey:

- **PurrNet's official EOS adapter exists.** Its documented setup requires PlayEveryWare's EOS plugin, EOSManager, product configuration and the host's Product User ID before connecting. That resolves adapter availability, but does not prove private-room discovery, identity recovery or migration coordination. The public migration package remains subscription-gated and exposes no substantive implementation documentation. PurrDiction migration compatibility is therefore **unverified, not known to be unsupported**. [Official adapter](https://purrnet.dev/docs/systems-and-modules/transports/eos-transport), [migration package](https://purrnet.dev/packages/hostmigration).
- **FishNet's paid label alone is not a strong reason to exclude it.** Official purchasing documentation lists $10 for initial downloads, optional $2/month updates, or $60 once for lifetime Pro/Project downloads. That could be cheaper than maintaining custom hitscan rewind, although it is outside a strictly zero-purchase requirement. Custom host migration is the more consequential gap; official docs explicitly say it is not built in. No purchase is proposed or authorized. [Pro access](https://fish-networking.gitbook.io/docs/overview/readme/pro-projects-and-support), [networking models](https://fish-networking.gitbook.io/docs/guides/high-level-overview/networking-models).

Compare total integration/maintenance work, recoverable player identity, join success through restrictive networks, host-loss behavior, recurring service limits, source access and exact supported versions. Benchmark claims from different demos cannot rank this game's latency or performance. Mirror, NGO and Netick remain documented alternatives; expanding each into a separate prototype is not justified by the current evidence.

**Research stopping point:** the remaining major questions require specific package compatibility evidence or controlled runtime tests, not another features list. After an explicit implementation resume, test Fusion and at most one challenger with the same motor, combat fixtures and network conditions. A modest paid add-on may be evaluated as an option; it must not silently replace the user's free-tool preference.

## Proposed comparison, only after explicit resume

First prove the compatible Fusion baseline using the foundation's small course and existing acceptance profiles. If source freedom, economics or a measured failure warrants comparison, add **one isolated PurrNet/PurrDiction + EOS experiment**, contingent on stable-version and migration feasibility. Do not build a multi-provider abstraction.

Audit sample-code and asset rights separately before reuse; Photon's sample-code permission does not automatically cover bundled assets. [Photon terms](https://www.photonengine.com/terms/licenseterms).

Use the same copied motor and fixtures: one hitscan, projectile, impulse, pickup and moving scoring volume. Compare external-network joins, forced relay, correction distributions, hit verdicts, host/client CPU and bandwidth, reconnect identity, abrupt host loss, rollback age and reconstruction of score/ammo/timers. Rotate hosts and test uneven teams. Report exact versions, hardware and effort alongside results; preserve the canonical budgets rather than inventing new pass marks.

Switch only if that experiment preserves the required recovery/security behavior and shows a meaningful maintenance, cost or measured performance benefit. Otherwise Fusion's integrated path remains the smaller solution.

**Evidence limits:** documentation/license/pricing research only. No SDK, Unity, Blender, account configuration, deployment or gameplay test ran. No existing source, spec, handoff, backlog or archive was changed; this new report is the sole project artifact.
